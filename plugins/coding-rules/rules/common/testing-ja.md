# テスト要件

## 最低テストカバレッジ: 80%

テストの種類（すべて必須）:
1. **ユニットテスト** - 個々の関数、ユーティリティ、コンポーネント
2. **インテグレーションテスト** - APIエンドポイント、データベース操作
3. **E2E テスト** - 重要なユーザーフロー（フレームワークは言語ごとに選択）

## テスト駆動開発

必須ワークフロー:
1. まずテストを書く（RED）
2. テストを実行 — 失敗すること
3. 最小限の実装を書く（GREEN）
4. テストを実行 — 成功すること
5. リファクタリング（IMPROVE）
6. カバレッジを確認（80%以上）

## テスト失敗のトラブルシューティング

1. **tdd-guide** エージェントを使用
2. テストの分離を確認
3. モックが正しいことを確認
4. テストではなく実装を修正する（テストが間違っている場合を除く）

## エージェントサポート

- **tdd-guide** - 新機能に対して積極的に使用。テストファースト開発を強制する
